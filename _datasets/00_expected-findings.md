> 这些是**真实算出来的数字**，不是估计。用它验收 skill：它应该独立发现同样的问题。

## 1. `03_text_dirty/chinese_orders_gbk.csv`（GBK 中文订单表）
- 行数 **4,000**，列数 12，文件 487 KB
- 编码级联实测：{'utf-8-sig': 'FAIL', 'utf-8': 'FAIL', 'gbk': 'OK', 'gb18030': 'OK'}  → 只有 gbk/gb18030 能读
- 空字符串（伪装成缺失值）：`客户`=291、`客户类型`=168
- 字面 `None` 当值：`折扣`=1047 行
- 订单号重复：**2075 行重复**（唯一订单号 1,925 个 / 共 4,000 行）
- 日期分布 Top3：[('2024-03-15', 1243), ('10/30/2018', 18), ('12/1/2018', 15)]（大量订单被压到同一天）

## 2. `02_multitable/movielens`（多表关联）
- ratings 100,836 行 / movies 9,742 行 / links 9,742 行
- 外键完整性：**0 个孤儿 movieId**（ratings 全部能在 movies 里找到）——这份数据的价值是“干净的多表关联”，不是脏数据；脏数据请用 03 目录

## 4. `03_text_dirty/bank_marketing.csv` + `superstore.csv`
- 银行营销：41,188 行 × 21 列，**分隔符是 `;`**（按 `,` 读会读成 1 列 41188 行）
- 真 NULL 为 0，但 `unknown` 是伪装缺失值：`job`=330、`marital`=80、`education`=1,731、`default`=8,597、`housing`=990、`loan`=990
- `pdays=999` 有 **39,673 行 / 共 41,188**（999=从未联系过的哨兵值；当数值算均值会严重失真）
- 目标列 `y` 极不平衡：yes 4,640 / no 36,548（正例率 11.3%）
- 超级商店：10,800 行 × 21 列，**有 19 列各缺 817 行**（该文件存在行长不齐的坏行，空缺集中在同一批记录上）
- 利润为负：1,871 行（亏损订单，占 17.3%）；订单号唯一 5,015 个 / 共 10,800 行

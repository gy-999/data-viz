# 大文件性能策略

> 来源：data-model-builder (DMB) 案例 15(GitHub 265K 行) + 案例 17(MovieLens 5480 万行)

## 判断标准

| 量级 | 策略 | 参考 |
|---|---|---|
| < 10 万行 | 全量加载，全量分析 | 不用管性能 |
| 10 万 ~ 100 万行 | 全量分块统计 + 抽样绘图 | DMB 案例 15 |
| > 100 万行 | 抽样预览（头 10 万行）+ 分块统计 | DMB 案例 17 |
| GB 级 SQL | 先解析 INSERT 估计行数，用户确认后分批 | 自研 SQL 解析器 |

## 千万行级建仓性能策略

| 策略 | 做法 | 为什么 |
|---|---|---|
| 分批写入 | 单事务 10 万行一批 executemany | 防日志膨胀 + 内存峰值 + 失败全回滚 |
| 关日志提速 | 中间处理阶段关日志（完成前恢复） | 日志是最大 IO 开销 |
| 内存封顶 | 设固定 cache_size（如 256MB） | 不封顶被大表扫描吃光内存 |
| 临时空间落盘 | temp_store = FILE | 千万行排序/聚合中间结果远超内存 |
| 抽样优先 | 先抽样预览，用户确认后全量 | 避免无意义等待 |

## 源库只读安全

| 策略 | 做法 |
|---|---|
| 只读附加 | MySQL 事务隔离 |
| 密码隔离 | 通过环境变量传入，不进 AI 上下文 |
| 探完断开 | 探源结束后立即关闭连接 |

## 写入安全

- 写出到 workspace 的 `output/` 目录
- 绝不修改源文件或源数据库
- 临时文件用 `_tmp/` 前缀，完成后清理

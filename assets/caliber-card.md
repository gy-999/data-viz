# 口径卡模板

> 来源：data-model-builder 实战 19 案沉淀，每个指标一张卡

## 口径卡模板

```markdown
### 口径卡：[指标中文名称]

**分子（什么条件下算）:**
```yaml
[大白话描述]
```

**分母（哪些记录进入统计范围）:**
```yaml
[大白话描述]
```

**只算什么:**
```yaml
[例：只算已归档工单]
```

**不算什么:**
```yaml
[例：未归档的不进分母；异常工单不记分子也不记分母]
```

**豁免规则:**
```yaml
[例：紧急变更不算超时；重试超过 3 次的算失败]
```

**更新周期:**
```yaml
日 / 周 / 月 / 实时
```

**AI 举例确认:**
> AI 问了什么？
> 1. "我看到源表有 500 条，其中 48.6% 还没支付。没支付的算进分母吗？"
>    用户答："没支付的暂时不算，我们只分析已支付的。"
> 2. "金额恰好 ¥10 的算吗？"
>    用户答："¥10 是免邮门槛，应该算。"

**业务方确认:**
```yaml
姓名: [业务方姓名]
日期: [YYYY-MM-DD]
```

**实现（口径卡引擎字段名）:**
```sql
-- 例：DWD 判定标签
case_when_[字段名] = CASE WHEN status IN ('paid','completed') THEN 1 ELSE 0 END
```
```

## 口径卡拍板 4 步流程

```
用户口述 ---------------------------------------- → Step 1: 用大白话说指标含义
    ↓
AI 拿真实数据举例确认 ---------------------------- → Step 2: "这条算不算？那条呢？"
    ↓ 边答边把口径精确化
AI 沉淀成口径卡 ---------------------------------- → Step 3: 填入上面模板
    ↓
代码实现 ----------------------------------------- → Step 4: 写入分析逻辑
```

## 注意事项

- **跨指标复用口径必须重新确认**：用户说"没发生的不管它"是就准时率说的。AI 扩展到"实收销售额剔除未发货"→ 推断合理但未经确认，导致偏差 2.6 万。口径的每一次跨指标复用都要回用户那里过一遍。
- **用户说"你定吧"=委托**：定完必须告知，并记入"AI 自主决策"清单（最终交付时给用户审阅）
- **反悔处理**：用户推翻已拍板的口径 → 立即停止推进 → 旧口径划掉留痕不删 → 新口径完整复述重新走 4 步
